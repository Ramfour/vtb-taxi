 Общее описание архитектурного стиля
Основная система представляет собой модульный монолит на базе фреймворка Laravel, обеспечивающий централизованное управление бизнес-логикой и данными. Дополнительно система включает внешние компоненты, интегрируемые через RESTful API.

Архитектура основной системы (Laravel):
1.	Веб-интерфейс — основной клиент для руководителей и администраторов
2.	Серверная часть (Backend) — ядро системы на Laravel с бизнес-логикой
3.	База данных — централизованное хранилище MySQL

Внешние компоненты системы:
• Telegram-бот (отдельный сервис на Python)
• Внешние API (геокодирование, уведомления)

Основная система взаимодействует с внешними компонентами через RESTful API, что обеспечивает слабую связанность и независимость компонентов. Выход из строя внешних компонентов не влияет на работу основной веб-системы.

🔄 Сценарии движения данных (потоки взаимодействия)

Сценарий 1: Подача заявки через внешние компоненты
1.	Внешний компонент (Telegram-бот) отправляет HTTP POST-запрос на эндпоинт API Laravel (POST /api/orders)
2.	Маршрутизатор Laravel направляет запрос в цепочку middleware:
o	API аутентификация проверяет токен внешнего сервиса
o	Проверка прав на создание заявки
3.	После успешной авторизации запрос попадает в контроллер, который делегирует выполнение Сервису управления заявками
4.	Сервис управления заявками создает запись в temp_requests со статусом pending
5.	Внешний компонент получает ответ о создании заявки

Сценарий 2: Обработка заявок через веб-интерфейс (основная система)
1.	Руководитель открывает веб-панель Laravel
2.	Через веб-интерфейс просматривает очередь заявок из temp_requests
3.	Выполняет действия (одобрить/отклонить/редактировать)
4.	Сервис управления заявками обновляет статусы и переносит одобренные в requests
5.	Формируется CSV-выгрузка через сервис генерации отчетов
Сценарий 3: Формирование и скачивание Excel-файла
1.	Руководитель в веб-интерфейсе нажимает кнопку «Экспорт в Excel»
2.	Запрос через Маршрутизатор поступает в Сервис генерации отчетов
3.	Сервис генерации отчетов запрашивает список одобренных заявок из таблицы requests
4.	С помощью PhpSpreadsheet создаётся CSV-файл для перевозчика
5.	Файл отдается пользователю для скачивания
6.	Заявки отмечаются как экспортированные (exported_at)

Сценарий 4: Аудит и логирование
1.	Все действия пользователей логируются в audit_log
2.	Записывается действие, пользователь, IP-адрес, время
3.	Логи используются для анализа и безопасности

🔗 Пояснения к ключевым связям (стрелкам)
Связь	Тип	Пояснение
Веб-интерфейс → Маршрутизатор	Синхронная (HTTP)	Классические запросы браузера к серверу (GET/POST). Используется сессионная аутентификация.
Внешние компоненты → API Laravel	Синхронная (REST API JSON)	Внешние сервисы отправляют данные на API-эндпоинты Laravel. Аутентификация по токенам.
Маршрутизатор → Модуль аутентификации	Внутренний вызов	Передача запроса через middleware-посредники для проверки прав.
Модуль аутентификации → Сервис заявок	Внутренний вызов	После успешной авторизации управление передаётся соответствующему сервису.
Сервис заявок → Буфер (temp_requests)	Синхронная (Eloquent ORM)	Все новые заявки немедленно сохраняются в буферную таблицу.
Сервис заявок → MySQL Database	Синхронная (CRUD-операции)	Чтение/обновление/удаление записей в таблицах requests и temp_requests.
Сервис заявок → Аудит (audit_log)	Синхронная (Eloquent ORM)	Запись всех действий пользователей в лог.
Сервис отчётов → Сервис заявок	Внутренний вызов	Получение данных, необходимых для генерации Excel.
Сервис отчётов → Excel-файл	Генерация файла	Создание и сохранение файла на диске / в памяти с последующей отдачей.

📝 Итоговое резюме по архитектуре
Спроектированная архитектура основной системы полностью отвечает требованиям дипломной работы:
•	Веб-интерфейс как основной клиент для руководителей и администраторов.
•	Централизованное управление бизнес-логикой и данными через ядро Laravel.
•	Двухэтапная обработка заявок с использованием буферной таблицы для контроля качества.
•	RESTful API для интеграции с внешними компонентами системы.
•	Модульность и слабая связанность компонентов, что упрощает тестирование, сопровождение и масштабирование.

Дополнительные компоненты системы:
•	Telegram-бот (отдельный сервис на Python) для удобства сотрудников
•	Внешние API для геокодирования и других сервисов
•	Все внешние компоненты взаимодействуют с основной системой через RESTful API
