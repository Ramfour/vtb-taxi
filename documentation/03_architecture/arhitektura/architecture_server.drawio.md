# Легенда: architecture_server.drawio

Файл: `_about/architecture_server.drawio` — схема “как работает сервер/хостинг” на уровне инфраструктуры.

## Элементы схемы

- **Клиенты**: браузер/телефон пользователей.
- **DNS**: записи домена (`A/AAAA`, `CNAME`), которые указывают на IP хостинга.
- **TLS termination (Let’s Encrypt)**: SSL-сертификат и шифрование соединения.
- **Web server (nginx/Apache)**: принимает HTTP(S) запросы и проксирует PHP-запросы в PHP runtime.
- **PHP runtime (PHP-FPM/CGI)**: исполняет PHP-код приложения.
- **Файлы приложения**: директория проекта; `public/` — “корень сайта” (docroot).
- **storage/**: записи сессий, логов, экспортов.
- **MySQL**: база данных проекта.
- **Cron**: планировщик на хостинге (в панели).
- **Laravel Scheduler**: механизм Laravel, который внутри запускает задачи по расписанию (например `taxi:cleanup`).
- **Бэкапы (рекомендация)**: регулярные резервные копии БД и важных файлов.

## Термины

- **DNS**: система доменных имен. Определяет, на какой сервер ведет `vtb-taxi.ru`.
- **A / AAAA**: DNS-записи для IPv4/IPv6.
- **CNAME**: DNS-алиас. Часто `www` указывает на основной домен.
- **TLS/SSL**: шифрование трафика; сертификат должен покрывать `vtb-taxi.ru` и `www.vtb-taxi.ru`.
- **Let’s Encrypt**: бесплатный CA, выпускает доверенные TLS-сертификаты.
- **nginx/Apache**: веб-сервер (может быть один из них).
- **FastCGI**: протокол связи веб-сервера с PHP-FPM.
- **PHP-FPM**: менеджер процессов PHP для веб-запросов (быстрее и стабильнее CGI).
- **CGI**: запуск PHP как отдельного процесса (на хостингах встречается как “PHP (CGI)”).
- **docroot**: “корневая директория сайта” — в Laravel это `public/`.
- **public/index.php**: входная точка Laravel, куда попадает каждый запрос.
- **storage/**: директория Laravel для runtime-файлов:
  - `storage/framework/sessions` — сессии при `SESSION_DRIVER=file`,
  - `storage/logs` — логи,
  - `storage/app` — прикладные файлы (например экспорты).
- **Cron**: задает расписание запуска команд.
- **Scheduler**: “внутренний cron” Laravel; для работы требует внешнего cron `schedule:run`.

## Типовая причина проблем (из опыта)

- Если CLI PHP отличается от web PHP, artisan-команды нужно запускать явным путем (например `/opt/php/8.3/bin/php artisan ...`).
- Для сессий/логов нужны права на запись в `storage/`.
