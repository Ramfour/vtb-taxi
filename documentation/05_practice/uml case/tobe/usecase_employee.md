# Use Case: Сотрудник (Employee)

Источник диаграммы: `usecase_employee.drawio`.

Диаграмма описывает минимальный набор действий, доступный пользователю с ролью **Employee** в веб-приложении.

## Актор

- **Сотрудник (Employee)** — создаёт заявки на такси и отслеживает их состояние.

## Сценарии (use cases) и что они означают

### 1) Войти в систему

**Смысл:** сотрудник проходит аутентификацию по табельному номеру и паролю.

**Связь с проектом (роуты):**

- `GET /login` → `login`
- `POST /login` → `login.store`

### 2) Подать заявку (`temp_requests`)

**Смысл:** создать новую заявку на поездку. Заявка попадает в буфер на согласование.

**Данные заявки (пример):**

- ФИО, телефон
- адрес
- дата и время поездки

**Связь с проектом (роуты):**

- `POST /employee/requests` → `employee.requests.store`

**Где хранится:** таблица `temp_requests`.

### 3) Посмотреть свои заявки

**Смысл:** сотрудник видит список созданных им заявок, их статусы и комментарии руководителя (если есть).

**Связь с проектом (роуты):**

- `GET /employee/requests` → `employee.requests.index`

### 4) Отменить заявку

**Смысл:** сотрудник может отменить ранее созданную заявку (пока это допустимо по бизнес-правилам).

**Связь с проектом (роуты):**

- `PATCH /employee/requests/{tempRequest}/cancel` → `employee.requests.cancel`

### 5) Сменить пароль

**Смысл:** пользователь может изменить пароль в своём аккаунте.

**Связь с проектом (роуты):**

- `POST /account/password` → `account.password.update`

## Важные замечания по безопасности

- Используется сессионная аутентификация (cookie + server-side session).
- Для форм используется CSRF-защита (Laravel middleware).
- Пароли в БД хранятся как хэш (bcrypt).
