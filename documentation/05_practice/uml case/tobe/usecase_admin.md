# Use Case: Администратор (Admin)

Источник диаграммы: `usecase_admin.drawio`.

Администратор обладает расширенными правами: управление пользователями и аудитом, плюс возможность выполнять действия руководителя.

## Актор

- **Администратор (Admin)** — обеспечивает эксплуатацию системы: контроль пользователей, аудит действий и доступ к ключевым операциям.

## Сценарии (use cases) и что они означают

### 1) Войти в систему

**Связь с проектом (роуты):**

- `GET /login` → `login`
- `POST /login` → `login.store`

### 2) Просмотреть пользователей (сотрудники/руководители)

**Смысл:** видеть список пользователей, их роли и состояние (активен/не активен).

**Связь с проектом (роуты):**

- `GET /manager/employees` → `manager.employees.index`

Примечание: в проекте список “employees” в интерфейсе админа фактически покрывает и сотрудников, и руководителей, а удаление доступно администратору.

### 3) Отключить / soft-delete пользователя

**Смысл:** деактивировать/удалить пользователя мягко (soft delete), чтобы сохранить историю.

**Связь с проектом (роуты):**

- `DELETE /manager/users/{user}` → `manager.users.destroy`

### 4) Force-delete пользователя

**Смысл:** окончательно удалить пользователя (жесткое удаление), если это нужно.

**Связь с проектом (роуты):**

- `DELETE /manager/users/{user}/force` → `manager.users.destroy-force`

### 5) Просмотреть аудит

**Смысл:** посмотреть журнал действий пользователей (кто/что/когда сделал), важный для прозрачности согласования.

**Связь с проектом (роуты):**

- `GET /admin/audit` → `admin.audit.index`

### 6) Скачать аудит CSV

**Смысл:** выгрузить аудит в CSV для отчетности.

**Связь с проектом (роуты):**

- `GET /admin/audit/export` → `admin.audit.export`

### 7) Согласование заявок (как Manager)

**Смысл:** администратор может выполнять операции руководителя по согласованию заявок.

Связь: см. `usecase_manager.md` и `manager.*` роуты.

### 8) Перенос + выгрузка CSV (как Manager)

**Смысл:** администратор может финализировать заявки и формировать CSV так же, как руководитель.

Связь: см. `usecase_manager.md`.

## Заметки по ответственности и рискам

- Soft-delete предпочтительнее force-delete, так как система хранит историю (аудит, заявки).
- Доступ к аудиту и массовым операциям — зона ответственности Admin: нужно аккуратно разграничивать права и учетные записи.
