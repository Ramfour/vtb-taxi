Шаг 0. Подготовка окружения (15–30 минут)
Создайте заготовку проекта, чтобы можно было сразу писать код.
1.	Docker:
o	docker-compose.yml с сервисами: nginx, php-fpm (Laravel), mysql, redis, phpmyadmin (опционально).
o	Важно: Пробросьте порт для локальной разработки и настройте volume для мгновенного обновления кода.
2.	Laravel:
o	composer create-project laravel/laravel taxi-vtb
o	Настройте .env на контейнеры Docker (DB, Redis).
o	Установите пакет для работы с Telegram API: composer require irazasyed/telegram-bot-sdk (или просто будете вызывать API через HTTP Client).
3.	База данных:
o	Создайте миграции прямо сейчас по вашим таблицам: users, invitations, temp_requests, requests, audit_logs.
o	Выполните php artisan migrate.
4.	Python бот:
o	Создайте отдельную папку bot в корне проекта.
o	Виртуальное окружение, установите aiogram.

Шаг 1. Ядро: Модели и аутентификация (Laravel) — Стартовая точка кода
Сейчас ваша главная задача — связать Telegram ID с пользователем в системе. Без этого ничего не поедет.
Порядок написания кода:
1.	Модель User:
o	Добавьте поле telegram_id (BIGINT) в миграцию и модель.
o	Добавьте трейт SoftDeletes.
o	Настройте Casts для шифрования полей (full_name, phone, default_address). Пример:
php
protected $casts = [
    'full_name' => 'encrypted',
    'phone' => 'encrypted',
    'default_address' => 'encrypted',
];
2.	API Контроллер AuthController:
o	Создайте маршрут POST /api/auth/telegram в api.php.
o	Логика метода: Принимает данные из Telegram Login Widget (проверка хеша обязательна). Ищет telegram_id в БД. Если есть — возвращает Sanctum Token. Если нет — возвращает ошибку "Пользователь не найден". Пока не разрешаем самодеятельную регистрацию (это через приглашения позже).
3.	Установка Laravel Sanctum для API токенов.
Чего не надо делать сейчас:
•	Сложную ролевую модель RBAC через Gate. Пока просто используйте middleware auth:sanctum и проверяйте роль if ($user->role === 'manager').

Шаг 2. Логика заявок: Буферная таблица (Laravel) — Самый важный код бэкенда
Создайте сервисный класс App\Services\TaxiOrderService. Это будет основная точка входа для всех операций с заявками.
Пишем методы в этом порядке:
1.	createTempRequest($user, $address, $dateTime):
o	Создает запись в temp_requests со статусом pending.
o	Ключевой момент: Не ждет геокодер. Диспатчит Job NormalizeAddressJob.
o	Возвращает ID заявки.
2.	NormalizeAddressJob (Job):
o	Вызывается через ShouldQueue.
o	Делает HTTP-запрос к Яндекс.Геокодеру.
o	Обновляет поле address_norm в temp_requests.
o	Важно: Если геокодер не ответил — оставляем address_norm пустым, но заявка должна жить.
3.	Методы для руководителя:
o	approve($tempRequestId, $managerId) — ставит status='approved' и manager_id.
o	reject($tempRequestId, $reason) — ставит status='rejected' и reason.
Совет по архитектуре:
Пока не усложняйте событиями и слушателями. В методах approve/reject просто в конце делайте вызов dispatch(new SendTelegramNotificationJob($userTelegramId, 'Ваша заявка одобрена')).

Шаг 3. Telegram Бот (Python) — Оживляем взаимодействие для сотрудника
Пока не пишите веб-интерфейс. Сотрудник должен иметь возможность заказать такси через бота уже на этом этапе. Это мотивирует.
Структура хэндлеров на aiogram 3.x:
1.	/start:
o	Бот должен получить telegram_id пользователя.
o	Отправить запрос к вашему Laravel API POST /api/auth/telegram.
o	Если Laravel вернул 200 и токен — сохраните токен в FSM хранилище бота (или просто в кэш по user_id). Сообщите: "Добро пожаловать, [Имя]".
o	Если 401 — "Обратитесь к руководителю для регистрации".
2.	/new_order:
o	Используйте машину состояний (FSM) для сбора данных: Адрес -> Время -> Подтверждение.
o	После сбора всех данных: POST-запрос в Laravel POST /api/orders (передаем токен в заголовке Authorization: Bearer {token}).
3.	Инлайн кнопки для статуса:
o	Сделайте команду /my_orders — отображает список заявок из temp_requests и requests (статусы).

Шаг 4. Веб-интерфейс руководителя (Laravel + Blade) — Управление
Теперь, когда бот умеет отправлять заявки, делаем панельку для руководителя на чистом Laravel Blade с Bootstrap (чтобы быстро).
Страницы и их контроллеры:
1.	/dashboard:
o	Таблица temp_requests со статусом pending.
o	Колонки: ФИО, Время, Адрес (исходный и нормализованный).
o	Кнопки: "Одобрить", "Отклонить".
o	При нажатии — AJAX запрос на POST /manager/orders/{id}/approve.
2.	/employees:
o	Таблица users. Кнопка "Пригласить сотрудника".
o	Генерация токена Str::random(32), сохранение в invitations.
o	Отображение ссылки для отправки сотруднику.
3.	/export:
o	Кнопка "Сформировать Excel".
o	Вызов метода ReportService::generateDailyReport().
o	Использование пакета PhpOffice/PhpSpreadsheet.
o	Отдача файла на скачивание.
Шаг 5. Интеграция: Финальный штрих
1.	Перенос заявок:
o	Добавьте в админ-панель кнопку "Перенести одобренные заявки в архив".
o	Вызов метода TaxiOrderService::moveApprovedToArchive().
2.	Журнал аудита:

Резюме: С чего начать писать код прямо сейчас?
1.	Откройте IDE, запустите Docker.
2.	Создайте миграции таблиц БД (15 минут работы).
3.	Напишите метод POST /api/auth/telegram в Laravel и проверьте его через Postman.
4.	Напишите команду /start в боте на Python, чтобы он авторизовывался через этот API.
5.	Создайте форму подачи заявки в боте и метод POST /api/orders в Laravel.
6.	Выведите эти заявки в тупой HTML-таблице в resources/views/dashboard.blade.php.
Как только вы увидите, что заявка из телеграм-бота появилась на веб-странице руководителя — считайте, что прототип работает. Всё остальное (нормализация, Excel, приглашения) — это полировка, которую можно добавлять постепенно.
