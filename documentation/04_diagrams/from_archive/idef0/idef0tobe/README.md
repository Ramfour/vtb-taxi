# IDEF0 (TO-BE): Описание Логики Диаграмм

Этот каталог содержит диаграммы IDEF0 в формате draw.io (`.xml`). Диаграммы описывают логику **текущего** проекта “Корпоративное такси”:

- интерфейс: веб-портал (Blade),
- backend: Laravel,
- БД: MySQL,
- основной поток: `temp_requests` (буфер) → согласование → `requests` (финальный слой) → экспорт `CSV`.

## Как читать IDEF0 (кратко)

IDEF0 описывает функцию и ее связи по модели ICOM:

- **Inputs (входы)**: данные, которые преобразует функция (обычно слева).
- **Outputs (выходы)**: результат работы функции (обычно справа).
- **Controls (управление)**: правила/ограничения, которые влияют на выполнение (обычно сверху).
- **Mechanisms (механизмы)**: кто/что выполняет функцию (люди, ПО, сервер) (обычно снизу).

## Набор диаграмм и что они означают

### 1) Контекст A0

Файл: `idef0_tobe0 ver 3 .xml`

**A0** — “Автоматизированная система корпоративного такси” как единая “черная коробка”.

- Входы: заявки сотрудников, запросы на отмену/удаление.
- Выходы: `CSV` для перевозчика, подтверждение/уведомления о статусе.
- Управление: регламент согласования + бизнес-правила валидации данных.
- Механизмы: веб-портал (сотрудник/руководитель), backend + БД.

### 2) Декомпозиция A0 → A1/A2/A3

Файл: `idef0_tobe1.xml`

**A0** раскладывается на 3 основные функции:

- **A1: Прием и валидация заявок**
  - формирование заявки сотрудником и сохранение в буфер.
- **A2: Согласование и управление заявками**
  - работа руководителя с очередью на согласование, редактирование/принятие решения, перенос одобренных в финальный слой.
- **A3: Экспорт подтвержденных поездок**
  - подготовка и выгрузка `CSV` на основе финального слоя.

Связи между функциями:

- из **A1 → A2**: заявки на согласование (буфер `temp_requests`);
- из **A2 → A3**: одобренные заявки в финальном слое (`requests`).

### 3) A1 — Прием заявки

Файл: `idef0_tobe A1.xml`

Детализация A1:

1. **A1.1: Прием заявки через веб-форму** (портал сотрудника).
2. **A1.2: Уточнение/нормализация адреса** (опционально, если требуется).
3. **A1.3: Валидация и сохранение в `temp_requests`**.

Выход A1: заявка на согласование в буфере `temp_requests`.

### 4) A2 — Согласование и перенос в финальный слой

Файл: `idef0_tobe A2.xml`

Детализация A2:

1. **A2.1: Просмотр очереди `temp_requests`** (фильтрация, поиск, просмотр деталей).
2. **A2.2: Редактирование заявок** (inline-редактирование нужных полей).
3. **A2.3: Принятие решений** (одобрить/отклонить, причина/комментарий, запрос уточнений).
4. **A2.4: Перенос одобренных в `requests`** (финализация данных).
5. **A2.5: Уведомления** (опционально).

Выход A2: одобренные заявки становятся строками в `requests` (финальный слой для экспорта).

### 5) A3 — Экспорт CSV

Файл: `idef0_tobe A3.xml`

Детализация A3:

1. **A3.1: Накопление и фильтрация данных** (на основе `requests`, по периоду/дате).
2. **A3.2: Генерация CSV** (формат, сортировка, пометка `exported_at`).
3. **A3.3: Предоставление и скачивание** (предпросмотр, скачивание руководителем).
4. **A3.4: Обработка ошибок** (логирование, уведомление админа).

Выход A3: `CSV`-файл для перевозчика.

## Соответствие диаграмм сущностям в БД (ориентир)

- `users`: пользователи и роли (**Employee/Manager/Admin**).
- `temp_requests`: буфер заявок “на согласовании” (очередь A2).
- `requests`: финальный слой (данные для A3).
- `audit_logs`: фиксация действий пользователей (кто/что/когда).
- `exported_at` (в `requests`): отметка, что строка уже выгружалась в CSV (используется для последующей очистки).

## Как экспортировать диаграммы в PNG

1. Открыть нужный `.xml` в diagrams.net (draw.io).
2. `File → Export as → PNG`.
3. Сохранить рядом или в отдельную папку для иллюстраций диплома.
