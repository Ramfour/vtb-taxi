# BPMN (miniBpmn): Описание Процесса

Файл диаграммы: `miniBpmn.xml` (формат draw.io / diagrams.net).

Эта BPMN-диаграмма показывает компактный сквозной процесс **подачи заявки сотрудником** и **согласования руководителем** в текущем проекте “Корпоративное такси”.

## Участники (дорожки / lanes)

В диаграмме используются 3 дорожки:

- **Сотрудник**: создает заявку через веб-форму.
- **Автоматизированная система**: принимает, валидирует и сохраняет данные в буфер.
- **Руководитель**: просматривает очередь, редактирует при необходимости, одобряет/отклоняет и переносит одобренные заявки в финальный слой.

## Термины, которые используются в процессе

- **Буфер заявок**: таблица `temp_requests` (заявки “на согласовании”).
- **Финальный слой**: таблица `requests` (одобренные заявки, источник для экспорта).
- **Перенос в основную БД** (в BPMN): фактически это финализация — перенос одобренных заявок из `temp_requests` в `requests`.

## Процесс по шагам (что означает каждый блок)

### 1) Подача заявки (дорожки “Сотрудник” → “Автоматизированная система”)

1. **Подать заявку через веб-форму (портал сотрудника)**  
   Сотрудник вводит ФИО, телефон, адрес, дату/время поездки.

2. **Валидация данных**  
   Система проверяет корректность полей (обязательность, формат и т.п.).

3. **Уточнение/нормализация адреса (по необходимости)**  
   Опциональный шаг: если нужно, адрес уточняется (в текущем проекте может быть ручное уточнение в интерфейсе, либо интеграция в будущем).

4. **Сохранить в буфер заявок (`temp_requests`)**  
   Заявка становится записью в `temp_requests` со статусом “на согласовании”.

5. **Уведомить руководителя**  
   В минимальном варианте руководитель видит заявку в своей очереди; при необходимости можно добавить уведомления (это не обязательно для работы процесса).

### 2) Согласование (дорожка “Руководитель”)

6. **Просмотр заявок в веб-интерфейсе**  
   Руководитель открывает страницу очереди заявок и выбирает нужные записи.

7. Развилка “Заявка корректна / Заявка не корректна”  
   Руководитель либо согласует заявку сразу, либо просит уточнения/вносит правки.

8. **Редактировать → Внести правки**  
   Руководитель исправляет данные (например, адрес/время/комментарий), если это возможно без участия сотрудника.

9. **Отклонить → Уведомить сотрудника (причина)**  
   Если заявка не проходит, руководитель отклоняет ее и указывает причину (сотрудник видит причину в интерфейсе).

10. **Одобрить**  
   Заявка получает статус “одобрено”.

11. **Перенос в основную БД**  
   В терминах проекта: перенос одобренной заявки из `temp_requests` в `requests` (финальный слой) для последующего экспорта в CSV.

### 3) Если требуется доп. информация

В диаграмме есть отдельная ветка “Требуется доп. информация” — это сценарий, когда руководителю не хватает данных.
На практике это означает, что заявка остается в буфере, пока данные не будут уточнены (через правки или повторную подачу).

## Как экспортировать miniBpmn в PNG (для диплома)

1. Открыть `miniBpmn.xml` в diagrams.net (draw.io).
2. `File → Export as → PNG`.
3. Вставить изображение в диплом в блок “Место для BPMN”.
