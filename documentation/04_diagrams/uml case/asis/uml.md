# AS-IS: UML Use Case (общая диаграмма)

Источники:

- `uml.xml`
- `uml.drawio` (исходник diagrams.net)

Диаграмма отражает раннее представление процесса “заказ/оформление такси” через обмен сообщениями и последующую обработку данных руководителем.

## Акторы

- **Сотрудник** — инициирует заявку/корректировку и получает обратную связь о статусе.
- **Руководитель** — проверяет, редактирует и подтверждает заявку, формирует ответ по статусу.

## Use cases (как задумано в AS-IS)

### Сотрудник

- **Отправить сообщение**: базовая операция, через которую сотрудник инициирует действие.
- **Отправить корректировку**: отправить правки по заявке.
- **Отменить заявку**: запрос на отмену.
- **Сменить адрес/время**: корректировка параметров поездки.
- **Получить уведомление о статусе заявки**: обратная связь от руководителя.

### Руководитель

- **Просмотреть статус заявки**: проверить текущую ситуацию по заявке.
- **Редактировать заявку**: исправить/уточнить данные.
- **Направить данные о статусе заявки**: отправить сотруднику результат рассмотрения.
- **Логировать изменение**: зафиксировать, что было изменено.

### Общие / поддерживающие

- **Валидация данных**: проверка обязательных полей, форматов и корректности.
- **Нормализация адресов (улица, номер дома)**: приведение адреса к “нормальному” виду.

## Связи include / extend (идея)

В диаграмме присутствует подпись **«include»**:

- **include** означает обязательный под-процесс, который выполняется всегда в рамках основного сценария.  
  Примерный смысл для AS-IS: “валидация данных” и “нормализация адресов” выполняются как часть обработки заявки.

Также в диаграмме есть примечание:

> include — обязательный вызов; extend — опциональное поведение при условии

То есть расширения (extend) могли бы применяться только при определённых условиях (например, “сменить адрес/время” как опциональная ветка), но в текущем файле основной акцент на include.

## Чем AS-IS отличается от текущей реализации (TO-BE / факт)

Сейчас проект реализован как веб-приложение с явными ролями и страницами:

- сотрудник подает заявку через веб-форму → `temp_requests`,
- руководитель согласует в интерфейсе → перенос в `requests`,
- экспорт в CSV,
- аудит действий в БД.

AS-IS полезен в дипломе как “история требований”, но текущий продукт ближе к TO-BE use-case диаграммам в папке `../tobe`.
