# Описание интерфейсов

Документ фиксирует интерфейсы проекта «Корпоративное такси». В системе два равноправных интерфейса:

- **Веб-портал** (Laravel + Blade) — основной, полнофункциональный.
- **Telegram-бот** (Python/aiogram) — дублирует ключевые действия веб-портала для всех ролей.

Оба интерфейса работают с одной MySQL-базой через единую бизнес-логику Laravel. Описание бота — в `documentation/07_bot_api_integration.md`.

Веб-проект не является SPA: интерфейс формируется сервером (Laravel + Blade). Пользователь работает в браузере, а после большинства действий получает обновлённую HTML-страницу и flash‑сообщение о результате.

## 1) Роли и доступ

В системе три роли. Роль действует одинаково в обоих интерфейсах (веб и бот):

- **Employee (Сотрудник)**: создание заявок, просмотр своих заявок (буфер + финальный слой), отмена Pending‑заявки, управление «быстрыми адресами» (только веб).
- **Manager (Руководитель)**: работа с очередью согласования, одобрение/отклонение, массовые действия (только веб), перенос одобренных заявок в финальный слой, выгрузка CSV (только веб), управление сотрудниками и приглашениями (только веб).
- **Admin (Администратор)**: все возможности руководителя + аудит, расширенное управление пользователями (в т.ч. «удалить навсегда») и возможность приглашать руководителей — всё только через веб-портал.

Права проверяются middleware'ом `role:*` и в отдельных действиях контроллера.

## 2) Общий каркас интерфейса

Единый layout: `resources/views/components/layouts/portal-vtb.blade.php`.

### 2.1 Шапка (Topbar)

Содержит:

- название/бренд проекта;
- заголовок и подзаголовок текущей страницы;
- «чип» аккаунта (ФИО, табельный номер, роль) для авторизованного пользователя;
- кнопку «Сменить пароль» (открывает модальное окно).

### 2.2 Навигация (nav-pills)

Пункты зависят от роли:

- **Главная**: `/`
- **Войти**: `/login` (только для гостя)
- **Мои заявки**: `/employee/requests` (для всех авторизованных)
- **Панель руководителя**: `/manager/requests` (Manager/Admin)
- **Сотрудники**: `/manager/employees` (Manager/Admin)
- **Аудит**: `/admin/audit` (только Admin)
- **Переключатель темы** (светлая/тёмная)
- **Выйти** (POST `/logout`, с подтверждением)

### 2.3 Flash‑сообщения и ошибки

Под навигацией выводятся:

- `session('status')` как «успешное» сообщение;
- список ошибок валидации, если `$errors->any()`.

### 2.4 Модальные окна

Есть две модалки:

- **QR приглашения**: используется на экране «Сотрудники» для удобной передачи ссылки.
- **Смена пароля**: доступна из шапки, отправляет POST на `/account/password`.

### 3.2 Вход

- URL: `GET /login`, `POST /login`
- Route name: `login`, `login.store`
- View: `resources/views/auth/login-modern.blade.php`

Форма:

- `employee_number` (табельный номер)
- `password` (пароль)
- кнопка «Показать» пароль (JS‑переключатель)

Логика после входа:

- если роль `Manager` или `Admin` → редирект в панель руководителя `/manager/requests`
- иначе → редирект в кабинет сотрудника `/employee/requests`

Ошибки:

- «Неверный табельный номер или пароль.»

### 3.3 Регистрация по приглашению

- URL: `GET /invite/{token}`, `POST /invite/{token}`
- Route name: `invitation.accept.show`, `invitation.accept.store`
- View: `resources/views/auth/accept-invitation-modern.blade.php`

Сценарий:

1. Пользователь открывает персональную ссылку.
2. Вводит данные профиля (ФИО, телефон, пароль, опционально «адрес по умолчанию»).
3. После успешной регистрации пользователь автоматически входит и попадает в `/employee/requests`.

Ограничения:

- приглашение одноразовое (`is_used=false`)
- может истечь по времени (`expires_at`)

## 4) Кабинет сотрудника

### 4.1 «Мои заявки»

- URL: `GET /employee/requests`
- Route name: `employee.requests.index`
- View: `resources/views/employee/dashboard-v2.blade.php`
- Доступ: Employee/Manager/Admin

Экран состоит из блоков:

1. **Новая поездка (форма)**
   - Поля:
     - `full_name` (ФИО, предзаполняется из профиля)
     - `phone` (телефон, предзаполняется из профиля)
     - `address_raw` (адрес подачи машины, textarea)
     - `date_time` (datetime-local)
   - Кнопка: «Отправить» (POST `/employee/requests`)
   - Валидация:
     - обязательные поля
     - `date_time` должен быть **в будущем** (`after:now`), иначе текст ошибки: «Возможно, у вас неправильная дата или время подачи машины уже прошло.»

2. **Быстрые адреса**
   - Назначение: хранить список часто используемых адресов сотрудника.
   - UI:
     - select со списком адресов (подстановка в `address_raw`)
     - поле добавления адреса
     - кнопки «Добавить» и «Добавить текущий»
     - список адресов с возможностью удаления
   - API (JSON):
     - `GET /employee/addresses` (получить список)
     - `POST /employee/addresses` (добавить)
     - `DELETE /employee/addresses/{address}` (удалить)

3. **Буфер: текущие заявки на согласовании** (`temp_requests`)
   - отображаются карточками со статусом, адресом, временем
   - если заявка Pending:
     - доступна форма отмены (PATCH `/employee/requests/{tempRequest}/cancel`)
     - поле: `reason` (причина отмены, опционально)

4. **История: финальные заявки** (`requests`)
   - показывает записи, перенесённые руководителем в финальный слой

Дополнительно:

- у сотрудника есть возможность смены пароля через модалку в шапке (общий механизм).

## 5) Панель руководителя

### 5.1 Главный экран руководителя (очередь + финальный слой + экспорт)

- URL: `GET /manager/requests`
- Route name: `manager.requests.index`
- View: `resources/views/manager/dashboard-v3.blade.php`
- Доступ: Manager/Admin

Экран объединяет 4 ключевых зоны:

1. **Сводка смены**
   - метрики: сколько всего в буфере, сколько Pending, сколько Approved (готовы к переносу)

2. **Очередь согласования (буфер `temp_requests`)**
   - сценарии:
     - просмотр заявок
     - одобрить/отклонить
     - массовое одобрение
     - (опционально) удалить запись из буфера (служебно)
   - действия по заявке:
     - PATCH `/manager/requests/{tempRequest}/review`
       - `action=approve|reject`
       - `manager_comment` (опционально)
       - `rejection_reason` (обязательно при reject)
     - POST `/manager/requests/bulk-approve`
       - `approve_scope=selected|all_pending`
       - `request_ids[]` (если selected)
       - `manager_comment` (опционально)
     - DELETE `/manager/requests/{tempRequest}` (служебное удаление)

3. **Перенос в финальный слой**
   - Назначение: после одобрения перенести записи из `temp_requests` в `requests`.
   - Действие: POST `/manager/requests/finalize`
     - фильтр диапазона `from/to` (nullable)

4. **Предпросмотр финального слоя (редактирование перед CSV)**
   - показывает `requests` в выбранном диапазоне `from/to`
   - позволяет править поля перед выгрузкой:
     - `full_name`, `address_raw`, `phone`, `date_time`
   - действия:
     - PATCH `/manager/final-requests/{finalRequest}` (сохранить)
     - DELETE `/manager/final-requests/{finalRequest}` (удалить навсегда, только Admin)

5. **CSV для перевозчика**
   - Назначение: выгрузка финальных заявок в файл.
   - Действие: POST `/manager/requests/export-csv`
     - `from/to` (nullable)
   - Кнопка «На сегодня (22:00–06:00)» выставляет диапазон дат на клиенте.

### 5.2 Экран «Сотрудники» (управление пользователями и приглашениями)

- URL: `GET /manager/employees`
- Route name: `manager.employees.index`
- View: `resources/views/manager/employees.blade.php`
- Доступ: Manager/Admin

Содержит:

1. **Создание приглашения**
   - POST `/manager/invitations`
   - поля:
     - `employee_number` (ровно 8 цифр)
     - `expires_in_days` (1..30, по умолчанию 7)
     - `role` (только для Admin: employee/manager)
   - результат: flash‑сообщение со ссылкой регистрации `/invite/{token}`.

2. **Список пользователей**
   - таблица с колонками:
     - ФИО, роль, табельный, телефон, адрес (последний), действия
   - поиск по ФИО/табельному/телефону (GET‑параметр `q`)
   - действия:
     - DELETE `/manager/users/{user}` (soft delete, доступно Manager/Admin, с ограничениями по ролям)
     - DELETE `/manager/users/{user}/force` (force delete, только Admin)

3. **Список последних приглашений**
   - отображает статус (использовано/ожидает) и срок действия
   - кнопки:
     - «Копировать»
     - «QR»
     - «Удалить приглашение» (DELETE `/manager/invitations/{invitation}`)

## 7) Смена пароля (встроенная функция аккаунта)

Смена пароля доступна всем авторизованным пользователям через модальное окно.

- URL: `POST /account/password`
- Route name: `account.password.update`
- Поля:
  - `current_password` (обязателен и проверяется)
  - `password` (min 8)
  - `password_confirmation` (должно совпасть)

Результат:

- flash‑сообщение «Пароль обновлён.»
- запись в аудит (`password_updated`)

## 8) Статусы заявок (общие правила отображения)

Статусы основаны на `App\Enums\RequestStatus`:

- `Pending` (1) — ожидает согласования
- `Approved` (2) — одобрена руководителем
- `Rejected` (3) — отклонена руководителем (обычно с причиной)
- `Cancelled` (4) — отменена сотрудником
- `Expired` (5) — истекла (служебный статус)

В UI статусы отображаются компонентом `x-status-pill` / `x-status-pill-v2` и используются для фильтрации/цветовых бейджей.
