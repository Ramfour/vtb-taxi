ВВЕДЕНИЕ

Научно-исследовательская работа в соответствии с ФГОС ВО по направлению подготовки 09.03.02 «Информационные системы и технологии» относится к блоку «Практики».

Цель работы — закрепление профессиональных умений и навыков проведения научно-исследовательской деятельности, закрепление теоретических знаний и практических умений и навыков в области информационных систем и технологий.

Тема исследования: разработка системы автоматизации заказа корпоративного такси для сотрудников отдела дистанционного клиентского обслуживания (ДКО) ПАО «ВТБ» в г. Новосибирске.

Основные решаемые задачи:
- владение способностью использования современных информационных технологий и программных средств в научно-исследовательской деятельности при решении профессиональных задач: методами поиска и анализа информации, современными инструментальными средствами по предметной области исследований;
- владение способностью применять математические модели, методы и средства проектирования при решении задач научно-исследовательской деятельности;
- владение основами деловой коммуникации на государственном языке РФ и иностранном языке в области информационных систем и технологий;
- владение приёмами системного подхода для структуризации финансовых вложений и возможных рисков.

Научно-исследовательская работа выполнялась в соответствии с полученным заданием, дневником практической подготовки и программой практики.

1 Описание предметной области, актуальность решаемой задачи

ПАО «ВТБ» — один из крупнейших банков России, осуществляющий полный спектр финансовых услуг для физических и юридических лиц. Объектом автоматизации является отдел дистанционного клиентского обслуживания (ДКО) новосибирского офиса ПАО «ВТБ». Сотрудники отдела регулярно используют корпоративное такси для служебных поездок.

В текущем состоянии процесс организации поездок выполняется вручную: заявки поступают через мессенджеры, электронную почту и устные обращения, руководитель вынужден самостоятельно консолидировать их в таблицу и формировать файл для перевозчика. Это создаёт накопительный эффект повторяющихся операций, риск потери заявок и ошибок при переносе данных.

Актуальность задачи определяется необходимостью автоматизации внутреннего цикла сбора, согласования и выгрузки заявок — участка процесса, который не покрывается ни внешними сервисами такси, ни универсальными CRM-системами в разумном объёме затрат.

private function buildCsvContent($requests): string
{
    $handle = fopen('php://temp', 'r+');
    fwrite($handle, "\xEF\xBB\xBF");
    fputcsv($handle, ['Номер', 'Дата и время', 'ФИО', 'Адрес подачи', 'Телефон'], ';');

    $index = 1;
    foreach ($requests as $requestRow) {
        fputcsv($handle, [
            $index,
            $requestRow['date_time'],
            $requestRow['full_name'],
            $requestRow['address'],
            $requestRow['phone'],
        ], ';');
        $index++;
    }

    rewind($handle);
    $content = stream_get_contents($handle);
    fclose($handle);

    return $content;
}

7 Проблемы, пути их решения, рекомендации

В ходе разработки и тестирования были выявлены следующие проблемы и найдены решения:

- **Проблема:** при развёртывании на хостинге некорректно работали сессии и логи.
  **Решение:** настройка прав на каталог storage, корректный .env для production.

- **Проблема:** при параллельной подаче заявок возможно дублирование на одно время.
  **Решение:** серверная проверка на дублирование по user_id + ride_at перед сохранением.

- **Проблема:** таблицы с большим числом заявок медленно отрабатывали фильтрацию.
  **Решение:** добавление индексов на поля status, user_id, ride_at в миграциях.

Рекомендации по дальнейшему развитию системы:
- реализация сервиса push-уведомлений об изменении статуса заявки;
- добавление аналитической отчётности по поездкам (частота, адреса, нагрузка);
- адаптация архитектуры для автоматизации других внутренних сервисов организации.
