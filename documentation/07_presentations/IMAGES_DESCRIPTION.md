# 📋 Описание изображений из презентации

## 🏗️ Архитектура системы (image5.png)

**Название проекта:** Корпоративное такси

**Основные компоненты:**

- **Веб-портал** - основной интерфейс для руководителей
- **Telegram-бот** - дополнительный интерфейс для сотрудников  
- **База данных MySQL** - централизованное хранилище данных

**Технологический стек:**

- Backend: PHP, Laravel
- Database: MySQL
- Bot API: Telegram
- Frontend: Blade, CSS

**Пользовательские роли:**

- Руководители (Manager)
- Сотрудники (Employee)
- Администраторы (Admin)

## 📊 Бизнес-процесс (image7.png)

**Этапы обработки заявок:**
1. **Создание заявки** - сотрудник подает заявку через веб или бот
2. **Согласование** - руководитель обрабатывает очередь заявок
3. **Экспорт** - формирование CSV файла для перевозчика

**Функциональные возможности:**

- Создание и редактирование заявок
- Массовая обработка
- История изменений
- Уведомления о статусе

## 📈 Статистика использования (image8.png)

**Метрики системы:**

- Количество заявок по месяцам
- Распределение пользователей по ролям
- Среднее время обработки заявок
- Пиковые нагрузки

**Эффективность:**

- Сокращение времени обработки
- Уменьшение ручных операций
- Повышение прозрачности процесса

## 🔧 Технические детали (image9.png)

**API архитектура:**

- RESTful эндпоинты
- JSON формат данных
- JWT аутентификация

**Безопасность:**

- HTTPS протокол
- Хеширование паролей bcrypt
- Ролевое разделение доступа
- CSRF защита форм

**Масштабирование:**

- Горизонтальное: балансировка нагрузки
- Вертикальное: оптимизация запросов

## 📱 Мобильный интерфейс (image10.png)

**Telegram-бот функции:**

- Создание быстрых заявок
- Проверка статуса заявок
- Получение уведомлений
- Управление адресами

**Преимущества бота:**

- Доступность 24/7
- Быстрый доступ к функциям
- Интеграция с мессенджером

## 🏗️ Детальная архитектура (Изображения/Архитектура.png)

**Слои архитектуры:**
